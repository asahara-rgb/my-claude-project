# 第1話ネーム レビュー（仕様書 v1 §3 に対して）

pages.json への転記時に気づいた点。**要修正**は転記側で暫定対応済み、**提案**は判断待ち。

## 要修正

1. **コマ順と右開きの読み順が逆**（P2〜P9 の中段・上段 2 分割すべて）
   ネームは「コマ2（中段左）→ コマ3（中段右）」の順で書かれているが、右開きでは右→左に読むので
   左が先だと会話が逆転する。例：P4 は「え……五分、とか。」（陽太）の後に「十五秒です。」（玲）が来るべき。
   → pages.json では **ネームの発話順を正としてコマを右→左に配置**し直した（コマ番号は `name` に残してある）。
   左右の指定が意図どおりなら、逆に台詞順を入れ替える必要がある。要確認。

2. **キャラ設定の誤植**：「妻から второй子の話が出て」→ ロシア語が混入。「第二子」。

3. **ASCII の「?」**（P2「慎重に?」P3「読み終わった?」P3「思います?」）
   縦書きでは全角「？」に統一。合成スクリプト側で自動変換するが、ネームも全角に揃えると校正が楽。

## 提案（セリフの温度感）

4. **P4 コマ3〜4 の情報量**：「企業の人事はもっと短い」「一つの求人に百通、二百通。全部を精読する時間は、物理的に存在しません」
   「書類選考は『読む』作業じゃない。『外す』作業なんです」が 2 コマ連続で玲の長台詞。
   コマ3 の 2 つ目の吹き出しを「百通、二百通。全部は読めない。」まで削ると、コマ4 の決め台詞が立つ。

5. **P7 コマ4 の「五十社落ちる」**：数字が強い分、玲が「説教しない」設定とややぶれる。
   「気づかないまま次の五十社に出す」のように行動描写にすると淡々さが保てる。

6. **P9 → P10 のつなぎ**：P9 コマ4 の決め台詞（伝え方を、一度も設計しなかった）と
   P10 コマ1 のモノローグ（読ませる書き方がある）が同じ結論を 2 回言っている。
   P10 コマ1 は「……設計、か。」程度に落として、コマ2 の行動（書き直し）で見せる案。

7. **P10 コマ3 の引き**「そして、四社目で――」の後に第2話予告が来るが、
   スマホ縦読みでは予告枕が引きの余韻を消す。予告は奥付側（巻末ページ）に移し、
   このコマは通知画面の絵と「四社目で――」だけで切る方が KU の「次話へ進む率」に効く。

## 画像生成プロンプトについて

8. P3 コマ1 の prompt は「a woman ... sitting across a small table」で、陽太の視点。
   キャラ一貫性のため `characters: ["rei"]` のみ付与し、陽太を描かせない構図にした。
   P9 コマ4（2 人が同時に映る）は一貫性リスクが最も高いコマ。ここだけ 8 案生成を推奨。

9. 脇役ルール（顔を出さない）に該当するのは P5 コマ1（人事の手元）のみ。`characters: ["_extra"]` で
   「手元のみ・顔なし」の固定文言が付く。

10. 仕様書の推奨ページサイズ 1200×1920 は Kindle 端末（Scribe 1860×2480、Paperwhite 1236×1648）や
    iPad では拡大表示になる。`style.json` の page_width / page_height を 1600×2560 に上げることを推奨
    （生成画像 1024×1536 を引き伸ばすので、生成側も 1536×2304 以上にするか、アップスケールを挟む）。
