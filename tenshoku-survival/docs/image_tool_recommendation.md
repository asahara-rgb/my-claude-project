# 画像生成ツールの選定メモ（2026年9月時点）

前提：モノクロ・スクリーントーンの青年漫画風、顔出しキャラ2名を約110ページ（36コマ×10話 ≒ 360コマ、案数×4で1,500枚前後）
一貫して描き続ける。セリフは描かせない。KDP には AI 生成申告。

## 結論

| 段階 | 使うもの | 理由 |
| --- | --- | --- |
| **今週：一貫性検証（20枚×2キャラ）** | **Gemini の画像生成モデル**（API・参照画像同送） | 参照画像を渡して「同じ人物」を保つのが現行の汎用モデルの中で強く、API があるので `00_character_test.py` からそのまま回せる。GPU 不要、1枚数円〜十数円 |
| 同上の比較対象 | **OpenAI gpt-image 系**（API・参照画像同送） | 指示追従が強く、コマ構図の言い分けに向く。モノクロ指定の再現は Gemini と比較して決める |
| **本番（一貫性が足りない場合）** | **Stable Diffusion XL 系アニメモデル（Illustrious / NoobAI 等）＋ キャラ LoRA ＋ ComfyUI** | 承認した参照画像 20〜30 枚で LoRA を学習すれば一貫性は最も高い。ComfyUI は API/CLI から叩けるので `--provider cmd` で接続。ローカル GPU か RunPod 等のクラウド GPU が必要。1枚あたりのコストはほぼ電気代 |
| 補助 | **NovelAI Diffusion** | アニメ・モノクロ漫画の絵柄が最も「漫画らしい」。キャラ参照機能あり。サブスク前提で API は非公式扱いなので、手動で使うか要確認 |
| 非推奨 | Midjourney | 絵は強いが公式 API が無く、1,500枚を手で回すのは非現実的。モノクロ漫画の制御もしにくい |

## 手順

1. `00_character_test.py sheet` で各キャラの参照シート（三面図＋表情）を生成し、**人間が納得する 2 枚を選んで `raw/refs/<key>_1.png`, `_2.png` に置く**。
   ここで妥協すると後の 1,500 枚すべてがブレる。10〜20 案出して選んでよい。
2. `00_character_test.py test --count 20` で 20 構図を生成 → `sheet-view` で一覧化 → 判定。
   - 16/20 以上で同一人物に見える：そのプロバイダで第1話へ（`01_gen_images.py --provider ...`）
   - 12〜15：プロンプトの服装・髪の記述を具体化し、参照シートを差し替えて再試行
   - 12 未満：LoRA 学習（または外注）へ切り替え。ここで判断を先送りしない
3. 第1話 36 コマ × 4 案を生成 → `pick` を選ぶ → `03_build_pages.py`

## 各ツールの注意

- **料金・モデル名は変わる**ので、実行前に各社の料金表を確認。`OPENAI_IMAGE_MODEL` / `GEMINI_IMAGE_MODEL` 環境変数でモデル名を差し替えられる。
- **商用利用と権利**：OpenAI / Google / NovelAI / Stability 系はいずれも生成物の商用利用を利用規約で認めている（2026年時点）。ただし利用規約は改定されるので、出版前に当該時点の規約を保存しておく。
- **KDP 申告**：どのツールでも「画像が AI 生成」を申告。加工（セリフ合成・トリミング）していても対象。
- **モノクロ指定**：汎用モデル（OpenAI / Gemini）はカラーで返すことがある。`03_build_pages.py` に `--grayscale` を付けると合成時にグレースケール化するが、線画の質感は生成時にモノクロで出た方が良い。プロンプト先頭の "black and white line art, screentone shading" は消さないこと。
- **セリフ・文字の混入**：negative_prompt に "text, letters, speech bubble" を入れているが、汎用モデルは看板や画面内文字を描くことがある。採用時に確認し、必要なら `pick` で別案へ。

## この環境で確認できなかったこと

API ドキュメント（platform.openai.com / ai.google.dev / docs.novelai.net）はネットワーク制限で参照できなかったため、
`scripts/providers.py` の openai / gemini アダプタは既知の仕様で書いた**未検証コード**。
最初は `--dry-run` でリクエストを表示 → 実行してエラーが出たら、そのメッセージに合わせてフィールド名を直す。
